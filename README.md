# وريف · نظام فريق العمل

نظام داخلي لمتجر وريف يغطي: الحضور والانصراف، التأخير والخروج المؤقت، كشف التلاعب، الخصومات والسلف، مسيّر الرواتب، العمليات اليومية (الطلبات حسب القناة، الشحنات، المرتجعات، مرتجعات التجار، البضائع الجديدة)، وتذاكر الملاحظات والإنجازات اليومية لكل موظف، مع تصدير يومي.

يحتاج **Node.js 22.13+** فقط، بدون أي مكتبات خارجية. قاعدة البيانات SQLite مدمجة في ملف واحد.

```bash
ADMIN_PASSWORD=كلمة-سر-قوية npm start   # http://localhost:3000
npm test                                 # 19 اختبار
```

## أول تشغيل

- يُنشأ حساب المدير تلقائياً: اسم المستخدم `admin` وكلمة المرور من `ADMIN_PASSWORD` (إن لم تحددها تُطبع كلمة مؤقتة في سجل التشغيل).
- يُنشأ الموظفون الستة بدون كلمات مرور: عبدالله `abdullah`، باسم `basem`، منذر `monther`، صفوان `safwan`، علي `ali`، عبدالملك `abdulmalik`.
- من **الموظفون**: حدد لكل موظف كلمة مرور وراتبه وفتراته، وفعّل «العمليات اليومية» لمن يسجّل الطلبات.
- من **الإعدادات**: راجع جدول الدوام، وأضف شبكة المحل أو موقعه للحماية من التلاعب.

## جدول الدوام الافتراضي

| الأيام | الفترات |
|---|---|
| السبت إلى الخميس | 7:00 ص – 12:20 م، و 1:00 م – 9:00 م |
| الجمعة | 2:00 م – 9:00 م |

فترة سماح التأخير 10 دقائق، وأقصى خروج مؤقت 30 دقيقة. كل شيء قابل للتعديل، ويمكن ربط كل موظف بفترات معينة (مثلاً صباحي فقط) وتحديد إجازته الأسبوعية.

## كيف يُحسب اليوم

- **التأخير**: من بداية الفترة إلى أول حضور فيها، ولا يُحسب إن كان ضمن فترة السماح.
- **الانصراف المبكر**: من آخر خروج إلى نهاية الفترة.
- **الخروج أثناء الدوام**: الخروج المؤقت (يحتاج سبباً) وأي فجوة داخل الفترة.
- **الغياب**: فترة كاملة بلا حضور. غياب الفترتين = غياب يوم، وغياب إحداهما = غياب جزئي.
- **الخصم المقترح**: أجر الدقيقة = الراتب ÷ 30 ÷ دقائق دوام ذلك اليوم. هو اقتراح فقط ولا يُخصم إلا إذا اعتمده المدير.
- الإجازات والأعذار المسجّلة تلغي حساب الغياب والتأخير لذلك اليوم.

## الحماية من التلاعب

- وقت البصمة من السيرفر دائماً، وتغيير ساعة الجوال يُعلَّم.
- لكل جوال معرّف؛ بصمة جوال واحد لأكثر من موظف تُعلَّم.
- بصمات من خارج شبكة المحل أو موقعه (إن حُددا) تُعلَّم، ويمكن إلزام تفعيل الموقع.
- الموظف لا يعدّل بصماته. كل إضافة أو إلغاء أو خصم أو تعديل من المدير يُحفظ في سجل التعديلات.

## التصدير

- **التقرير اليومي**: صفحة جاهزة للطباعة أو الحفظ PDF، وملف Excel (CSV) شامل لكل أقسام اليوم.
- ملفات منفصلة للحضور لفترة، مسيّر الرواتب الشهري، العمليات والبضائع، التذاكر، والسلف.
- نسخة احتياطية تلقائية يومياً في `/data/backups` (تُحفظ 30 يوماً)، وتنزيل نسخة كاملة من صفحة التقارير.

## النشر على Railway

1. أنشئ مشروعاً جديداً من هذا المستودع (يستخدم `Dockerfile` تلقائياً).
2. أضف **Volume** على المسار `/data`، وإلا ضاعت البيانات مع كل نشر.
3. المتغيرات: `ADMIN_PASSWORD` (إلزامي)، و `SECURE_COOKIES=1`.
4. بعد النشر افتح الرابط من جوال كل موظف، ومن قائمة المتصفح اختر «إضافة إلى الشاشة الرئيسية» ليصبح مثل التطبيق.

البصمة بالموقع تتطلب HTTPS (Railway يوفره).

| المتغير | الوصف |
|---|---|
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` / `ADMIN_NAME` | حساب المدير الأول |
| `DB_PATH` | مسار قاعدة البيانات (افتراضي `/data/staff.db` في Docker) |
| `TZ_OFFSET` | المنطقة الزمنية (افتراضي `+03:00`) |
| `SECURE_COOKIES` | `1` خلف HTTPS |
| `BACKUP_KEEP_DAYS` | عدد أيام النسخ الاحتياطية (افتراضي 30) |
